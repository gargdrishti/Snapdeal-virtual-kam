# Submission Note: Snapdeal Virtual KAM (mini)

**Idea.** Not a Q&A bot: an agent that owns the seller's problem. It reads the data first, diagnoses, asks only the questions the data cannot answer, ranks causes in rupees, recommends 2-3 actions, then *does* them (restock task, ticket, follow-up call, WhatsApp summary) and commits to calling back.

**Voice pipeline.** Browser mic -> Web Speech API (speech-to-text, en-IN / hi-IN, streaming interim text) -> Node/Express `/api/chat` -> LLM agent loop with tools -> reply text -> speech synthesis (browser voice, or ElevenLabs `eleven_multilingual_v2` if a key is set) -> speaker. Replies are capped at 2-3 sentences, one question at a time, to feel like a call. Optional barge-in lets the seller interrupt.

**AI models.** Gemini (`gemini-2.5-flash`, function calling) or Claude (tool use); selectable by env key. Tool-calling keeps numbers grounded: the model must fetch metrics instead of guessing. An offline state-machine brain using the same tools is the fallback if the network or API fails, so the demo never breaks.

**Workflow.** (1) Open: greet, or proactive call that names the sales drop. (2) Diagnose: metrics show average price flat at Rs 500 so pricing is ruled out; the drop is volume (orders -32%). (3) Investigate: out-of-stock 5 -> 18 (13 newly OOS products were 26% of last month's orders), cancellations 8% -> 14% (22 of 44 due to stock unavailable), impressions about -35%. Ask: why stock ran out, dispatch time, any listing/ad changes. (4) Quantify with `estimate_impact`: about Rs 26k stock-outs, Rs 9.5k extra cancellations, Rs 29.5k visibility/other of the Rs 65k drop. (5) Recommend: restock top 5 sellers; speed dispatch and auto-pause zero-stock listings; promo once stock is back. (6) Act and summarise: tasks created, follow-up in 48h, summary sent.

**Assumptions (mock data, clearly marked in `lib/data.js`).** Orders are net of cancellations (gross = orders / (1 - cancel rate)); the 13 newly OOS products, their days out of stock, cancellation reason split, impressions/CTR and a 48h dispatch SLA are invented. Stock-out loss = last-month orders of those products x share of month unavailable; the remainder is attributed to visibility/other and is partly linked to stock-outs (they lower search rank). No Snapdeal data or systems are used.

**Ownership beyond the call.** The agent does not stop at advice: it creates the restock task, ticket, follow-up and WhatsApp summary, and a built-in "fast-forward 48 hours" call shows it closing the loop (checking progress against its own promises, naming what is pending, agreeing next steps). A frustration/human-request detector hands off to a senior KAM with a context summary.

**Rough cost per call (estimate).** A call is about 6-8 turns; with tool loops that is roughly 15 LLM requests and about 20-30k input and 2k output tokens with a flash-class model, so LLM cost is a small fraction of a rupee per call. Voice (STT/TTS) dominates the cost if a premium service is used; browser voice is free. Compare with the cost of a human KAM minute on every seller, which is why a Virtual KAM can cover the long tail of sellers.

**Trade-offs and next steps.** Browser speech APIs keep setup to zero but need Chrome/Edge and sound less natural than a streaming voice platform (Vapi / ElevenLabs agents / Gemini Live would cut latency and handle interruptions better). With real data I would add live catalogue and order APIs, real ticketing, per-seller memory across calls, seller-side outcome tracking to validate recommendations, and an eval set of call transcripts.
